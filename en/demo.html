Error Correction Plugin

Makes journalistic corrections more visible and trackable. Works on any CMS: just include the CSS and JS from this page and add data-ec-* attributes to your HTML.

Example: article with corrections

UN Security Council calls emergency meeting after escalation in Iran

By Ana Martins · April 17, 2026, 9:42 AM

At an extraordinary session held Friday morning, the UN Security Council approved a resolution calling for restraint from all parties involved in the conflict. Fourteen countries voted in favor of the resolution, with one abstention and no votes against.

The resolution text demands an immediate end to hostilities and the return of the parties to the negotiating table. According to diplomatic sources consulted by this outlet, the vote reflects a rare alignment among permanent members of the Council.

Update (2:20 p.m.): the State Department issued, in a statement released minutes after the vote, that the United States considers the result "a victory for multilateralism" and will continue to support diplomatic efforts at the Security Council.

Patterns beyond error corrections

The plugin also supports three patterns that go beyond "fixing an error": new content (added after publication), right of reply (court-granted text) and removed passage (record of a deletion). Each below is a standalone demonstration, with the data attributes visible in the source.

→ New content · data-ec-new

Yellow box with the "NEW · ADDED Xh AGO" label. After 24h, the visual marking disappears and the text remains as a normal paragraph. Bold lead-ins (<strong>Update (HH:MM):</strong>) are also automatically stripped.

Update (1:50 p.m.): international agencies confirmed that the U.N. Secretary-General will personally attend next week's session — information not available in the first version of this story, which named only the permanent representative.

→ Removed passage · data-ec-removed

Gray dashed block: records the removal with reason + collapsible original text. After 24h, the entire block (including the original text) disappears from the page, leaving the definitive version in the public archive.

→ Right of reply · data-ec-reply

Permanent teal block. Publishes the full text of a court-granted reply, with reference to the ruling and credit to the requesting source. Does not vanish — it is part of the public record.

How to install on any CMS

1. Copy the CSS and JS

Open this file in an editor and copy everything between the markers ▼ PLUGIN START ▼ and ▲ PLUGIN END ▲ — two blocks, one in <style> and one in <script>. Paste into your CMS templates (WordPress, Ghost, Drupal, Sanity, etc.) or host as two static files (ec.css, ec.js).

2. Mark inline corrections in the text

Whenever a word or phrase is corrected inside the article body, wrap the new text in a <span> with the attributes below. The plugin adds a visual highlight and a tooltip showing the original text.

<span data-ec-inline
      data-ec-before="Fifteen countries voted in favor"
      data-ec-reason="Correction: there were 14 votes, not 15.">
  Fourteen countries voted in favor
</span>

3. Insert a correction block

At the top or bottom of the article, add a <div> with the correction metadata. The plugin renders a card with type badge, date, reason, and a before/after diff.

<div data-ec-block
     data-ec-type="factual"
     data-ec-title="Correct number of votes"
     data-ec-reason="The initial version reported 15 countries; the correct number is 14."
     data-ec-before="Fifteen countries voted in favor."
     data-ec-after="Fourteen countries voted in favor."
     data-ec-date="2026-04-17T14:20:00-04:00">
</div>

Possible values for data-ec-type: factual, spelling, imprecision, statement, other. This taxonomy is aligned with the one used in the research landing page (see README): factual (red) for factual errors, spelling (indigo) for spelling/typo errors, imprecision (orange) for vague info or imprecise numbers, statement (purple) for errors in quotes or testimony, and other for cases that don't fit elsewhere.

4. Show the corrections archive

On an archive page or at the end of the article, include the container. The plugin lists every correction from the page and adds filters.

<div data-ec-list
     data-ec-title="Corrections to this coverage"
     data-ec-subtitle="Auditable list of every correction.">
</div>

5. Report error button

Anywhere in your template, add a <button> with the data-ec-open-form attribute. The plugin binds the click to open the modal.

<button data-ec-open-form class="ec-report-button">
  Report an error
</button>

For a fixed floating button, enable it in the JS config (see step 9).

6. Right of reply

When a source obtains a court-granted right of reply, use data-ec-reply. The plugin renders a permanent teal block with the full reply text, the court ruling reference, and credit lines.

<div data-ec-reply
     data-ec-from="Senator X"
     data-ec-ruling="U.S. District Court for D.C. · case no. ..."
     data-ec-date="2026-04-17T16:45:00-04:00"
     data-ec-intro="In compliance with the court order..."
     data-ec-text="I want to make clear that my remarks were taken out of context..."
     data-ec-footer="Published in full, without editorial revision, as ordered by the court.">
</div>

7. Removed passage (vanishes after 24h)

When a passage is removed after publication, use data-ec-removed. The plugin renders a gray dashed block with the reason and an option to expand the original text. Important: the entire block (including the original text) automatically disappears from the page after 24 hours, leaving only the definitive version in the public archive.

<div data-ec-removed
     data-ec-reason="unverifiability"
     data-ec-flagged-by="World Desk Editor"
     data-ec-date="2026-04-17T15:10:00-04:00"
     data-ec-explanation="The first version attributed to anonymous sources..."
     data-ec-original="The verbatim text that used to be there.">
</div>

8. New content / update (marking goes after 24h)

To highlight a passage added after initial publication — a context update, a new quote, a new reaction — use data-ec-new. The plugin wraps the content in a yellow box with a "New · added Xh ago" badge. After 24 hours, the yellow box and the badge vanish; the text remains in the article flow (and any bold lead-in like "Update (HH:MM):" is also stripped so the text reads as regular article copy).

<div data-ec-new data-ec-date="2026-04-17T14:20:00-04:00">
  <p><strong>Update (2:20 p.m.):</strong> new content here...</p>
</div>

9. "Recently published" indicator (last 24h)

The plugin automatically applies the .ec-recent class and a badge to corrections whose data-ec-date is within the last 24 hours. The same window governs the expiry of data-ec-removed and data-ec-new blocks. The window is configurable.

10. Advanced configuration (optional)

If you want to customize behavior, call ErrorCorrection.init() before the closing </body>. All options are optional.

<script>
  ErrorCorrection.init({
    // URL for error reports (POST JSON)
    endpoint: "/api/report-error",

    // "Recent" window in hours (default: 24)
    recentWindowHours: 24,

    // Show floating report button
    floatingButton: true,
    buttonPosition: "bottom-right", // or bottom-left, top-right, top-left

    // Callback instead of (or alongside) endpoint
    onReport: function(data) {
      console.log("Error reported:", data);
      // data: { type, description, email, url, sentAt }
    },

    // Override interface text (i18n / editorial voice)
    labels: {
      reportButton: "Report an error",
      modalTitle: "Report an error",
      modalSubtitle: "Every correction is reviewed by editors before publication.",
      // ...other labels in ErrorCorrection.defaultLabels
    }
  });
</script>

11. Programmatic API

If your CMS already stores corrections in a database, render them from JS instead of data-ec-block:

ErrorCorrection.register([
  {
    type: "factual",
    title: "Correct spelling of the spokesperson's name",
    reason: "The initial text had 'John Smith' — the correct name is 'George Smith'.",
    before: "John Smith",
    after: "George Smith",
    date: "2026-04-17T10:12:00-04:00"
  }
]);
ErrorCorrection.renderList(document.querySelector("#corrections-archive"));
Accessibility and compatibility
  • Keyboard navigation: modal opens with Enter/Space, closes with Esc.
  • Focus management: opening the modal moves focus to the first field; closing returns focus to the trigger.
  • No external dependencies (plain HTML, CSS, and JS). Works with any CMS.
  • The .ec-* and data-ec-* namespace prevents collisions with your existing theme.
  • Compatible with modern browsers (Chrome, Safari, Firefox, Edge — last 2 versions).
