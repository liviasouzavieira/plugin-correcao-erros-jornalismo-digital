O que é este manual

Este manual é um guia prático para você, estudante de jornalismo, publicar notícias no portal de notícias da universidade com transparência sobre correções e atualizações. Ele parte de uma pergunta simples: o que fazer quando a gente erra?

A resposta curta: admitir, explicar, corrigir visivelmente. A resposta longa — que é este manual — está em como fazer isso dentro do WordPress, usando o plugin que a redação do portal já tem instalado.

Você vai aprender a publicar uma matéria do zero, inserir correções quando elas forem necessárias, escolher o padrão certo para cada tipo de erro e evitar as armadilhas mais comuns.

Por que isso importa: uma pesquisa realizada em 200 sites de notícias brasileiros em 2025 mostrou que apenas 1,5% têm uma seção dedicada a correções — e 0% dos erros detectados em dez grandes sites durante dois meses de monitoramento resultaram em erratas publicadas. Esconder erro é prática dominante no jornalismo brasileiro. Este manual é um convite para fazer diferente.

O plugin de correção, em uma frase

O Plugin de Correção de Erros é uma ferramenta instalada no WordPress do portal que transforma marcações simples no código HTML em sinalizações visuais padronizadas para o leitor: quadros coloridos de correção, marcações inline, blocos temporários de "conteúdo novo", caixas de "trecho excluído", espaço para direito de resposta, botão de reportar erro e seção agregadora de correções.

Você não precisa saber programar para usá-lo. Precisa saber copiar e colar código no editor do WordPress — e preencher os campos que o plugin pede.

Qual editor do WordPress você vai usar

O WordPress oferece hoje três tipos de editor diferentes, dependendo de como o portal foi configurado:

1. Editor Clássico (TinyMCE)

O editor "antigo" do WordPress, com barra de ferramentas no estilo Word (botões de B, I, lista, etc.). Tem duas abas no canto superior direito: Visual e Código. É o mais usado em sites universitários que não migraram para Gutenberg.

2. Gutenberg (editor de blocos)

Introduzido em 2018, trabalha com "blocos" independentes. Para inserir HTML, você usa o bloco "HTML personalizado", que se busca clicando no botão + dentro da página de edição.

3. Elementor (page builder)

Plugin separado, usado em muitos portais universitários pela facilidade visual. Quando um post tem Elementor, aparece um botão azul "Editar com Elementor" no topo. Para HTML, use o widget HTML arrastando para a página.

Importante para TODOS os editores: cole o código HTML das correções sempre em modo "código" ou "HTML", nunca no modo visual. O editor visual limpa automaticamente os atributos data-cde-*, e o plugin para de funcionar — você vai ver o texto, mas sem as caixas coloridas de correção.

Passo a passo: publicar uma notícia (sem correção)

Antes de aprender as correções, vamos ao básico: como publicar uma matéria normal no portal.

  1. Faça login no painel do WordPress em seu-site.com.br/wp-admin. Use seu usuário e senha da redação.
  2. No menu lateral esquerdo, clique em Posts → Adicionar novo.
  3. Digite o título da matéria no campo que aparece no topo. O título gera automaticamente o link permanente (URL) da notícia.
  4. Clique no corpo do editor e digite ou cole o texto da matéria. Formate como quiser: parágrafos, subtítulos (H2, H3), negrito, itálico, listas.
  5. Adicione uma imagem destacada no painel lateral direito, em "Imagem destacada". Essa é a imagem que vai aparecer na home do portal e nas redes sociais.
  6. Selecione a categoria no painel direito (Notícias, Entrevista, Cobertura, etc.) e adicione tags relevantes.
  7. Confira a prévia clicando em "Visualizar" (olho) no topo. Veja como a matéria vai ficar antes de publicar.
  8. Clique em "Publicar" (botão azul no canto superior direito). Pronto — a matéria está no ar.

Como inserir uma correção na matéria já publicada

Quando um erro é identificado — pelo editor, por um leitor, pela própria fonte — você precisa editar a matéria original e inserir um bloco de correção no local apropriado. Nunca crie uma segunda matéria para corrigir a primeira.

Fluxo geral (vale para qualquer tipo de correção)

  1. Abra a matéria publicada: no painel, vá em Posts → Todos os posts → clique no título da matéria com erro.
  2. Vá para o modo Código: se o editor Clássico está aberto, clique na aba Código no canto superior direito. No Gutenberg, use o bloco "HTML personalizado". No Elementor, abra o widget HTML onde o texto está.
  3. Localize o ponto onde a correção vai: identifique onde o leitor precisa ser avisado da correção. Para erros no corpo, insira o bloco logo depois do parágrafo errado. Para correções que afetam toda a matéria, insira no início ou no fim.
  4. Cole o bloco de correção: copie o código do padrão apropriado da Parte IV deste manual e cole no local certo.
  5. Preencha os campos: ajuste todos os campos data-cde-* para refletir a correção específica. Datas no formato AAAA-MM-DDTHH:MM:SS.
  6. Corrija o texto do corpo da matéria também: o bloco de correção não substitui o texto corrigido — ele registra que a correção aconteceu. O texto do corpo precisa ser atualizado para a versão correta.
  7. Clique em "Atualizar" (botão azul). A matéria é atualizada mantendo a mesma URL original.
  8. Confira o resultado: visite a página pública da matéria e verifique se o bloco de correção aparece corretamente, com a cor certa, os textos nos lugares corretos.
Nunca: apague a matéria publicada para republicar uma versão corrigida com nova URL. Isso cria desinformação — leitores que compartilharam o link original chegam a um erro 404 e perdem a correção.

Como escolher o padrão certo para cada caso

O plugin oferece onze padrões diferentes, cada um para uma situação específica. Essa árvore de decisão ajuda a escolher rápido:

É um erro?

  • Erro de número, atribuição ou fato objetivo? → use 1. Erro factual (vermelho)
  • Erro de digitação ou grafia que mudou o sentido? → use 2. Erro de grafia (azul escuro)
  • Informação vaga ou imprecisa que ganhou precisão? → use 3. Imprecisão (laranja)
  • Uma fala citada saiu errada? → use 4. Retificação em declaração (roxo)
  • O caso não encaixa em nenhum dos acima? → use 5. Outro (cinza)
  • É uma correção pontual de uma palavra ou expressão no meio do texto? → use 6. Marcação inline (rosa)

Não é erro, é outro tipo de modificação?

  • É informação nova que foi acrescentada (nota oficial, desdobramento)? → use 7. Conteúdo novo (amarelo, 24h)
  • Um trecho precisou ser removido da matéria? → use 8. Trecho excluído (cinza tracejado, 24h)
  • É um direito de resposta judicial ou por acordo? → use 9. Direito de resposta (verde-azulado, permanente)

Elementos estruturais da matéria/portal:

  • Quer deixar o botão de reportar erro ao final da matéria? → use 10. Botão (preto)
  • Quer criar uma página agregando todas as correções do portal? → use 11. Seção agregadora (rosa)
1

Erro factual

Cor: vermelho

Quando usar

Use quando a notícia publicou uma informação objetivamente errada: um número, uma data, uma atribuição, uma identificação de pessoa, local ou fato que não corresponde à realidade.

Exemplos de situação

  • O número de alunos matriculados foi divulgado como 12 mil quando o correto é 15 mil
  • Uma pesquisa foi atribuída a um pesquisador quando o autor é outro
  • A data da inauguração do laboratório foi informada como 10 de outubro quando foi 10 de novembro
  • O título do livro recém-publicado pela universidade apareceu com nome errado

Campos a preencher

Obrigatórios: tipo, motivo, data
Opcionais: titulo, antes, depois

Dica de ouro

O erro factual exige o antes/depois explícito. É o tipo de correção que precisa da maior transparência possível, porque está sendo admitido um erro objetivo. Pedir desculpas no campo motivo é uma boa prática.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-bloco
     data-cde-tipo="factual"
     data-cde-titulo="Correção — número de matriculados"
     data-cde-motivo="Em versão anterior desta matéria, informamos que a UFBA tem 12 mil alunos de graduação matriculados em 2026. O número correto, segundo a Pró-Reitoria de Ensino de Graduação, é 15 mil. A informação foi corrigida e pedimos desculpas pela falha."
     data-cde-antes="A UFBA conta com 12 mil alunos de graduação em 2026."
     data-cde-depois="A UFBA conta com 15 mil alunos de graduação em 2026."
     data-cde-data="2026-10-07T14:30:00">
</div>
2

Erro de grafia

Cor: azul escuro

Quando usar

Use quando um erro de digitação ou ortografia mudou o sentido da frase ou prejudicou a identificação de uma pessoa, lugar ou instituição. Não é para toda troca de letra — só para as que afetam a compreensão.

Exemplos de situação

  • O nome da professora saiu grafado como "Maria Souza" quando o correto é "Maria Sousa"
  • O nome do curso foi escrito como "Comunicação Sosial" em vez de "Social"
  • Uma palavra importante na declaração foi trocada: "ele não concorda" em vez de "ele concorda"
  • Troca de letra em sigla importante — "UFPA" no lugar de "UFBA"

Campos a preencher

Obrigatórios: tipo, motivo, data
Opcionais: titulo, antes, depois

Dica de ouro

Nem todo erro de digitação precisa de uma errata. A regra prática: se o erro de letra alterou o sentido ou confundiu a identificação de alguém, é correção de grafia. Se foi um "desta" em vez de "deste" sem afetar a compreensão, é correção silenciosa comum.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-bloco
     data-cde-tipo="grafia"
     data-cde-titulo="Correção ortográfica — nome da professora"
     data-cde-motivo="Em versão anterior, o nome da professora da Faculdade de Comunicação apareceu grafado como 'Maria Souza'. O nome correto é 'Maria Sousa', conforme o registro acadêmico oficial da UFBA."
     data-cde-antes="A pesquisa, coordenada pela professora Maria Souza"
     data-cde-depois="A pesquisa, coordenada pela professora Maria Sousa"
     data-cde-data="2026-10-07T15:00:00">
</div>
3

Imprecisão / Esclarecimento

Cor: laranja

Quando usar

Use quando a notícia tinha uma informação vaga, imprecisa ou incompleta que ganhou mais acurácia depois. Não é necessariamente um erro grave — é um refinamento que precisa ser transparente para o leitor.

Exemplos de situação

  • A matéria dizia "cerca de 500 pessoas participaram do evento" e depois a assessoria confirmou que foram 623
  • O prazo foi informado como "os próximos meses" e a reitoria esclareceu que são 90 dias
  • A verba foi descrita como "milhões de reais" e depois você soube que são R$ 2,3 milhões
  • A notícia dizia que o estudo foi "recentemente publicado" quando ele é de 2020

Campos a preencher

Obrigatórios: tipo, motivo, data
Opcionais: titulo, antes, depois

Dica de ouro

Imprecisão não é a mesma coisa que erro factual. Erro factual = informação errada. Imprecisão = informação vaga que ficou precisa. O título do campo titulo pode ser "Esclarecimento" em vez de "Correção" — faz diferença de tom.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-bloco
     data-cde-tipo="imprecisao"
     data-cde-titulo="Esclarecimento — número de participantes"
     data-cde-motivo="A versão original informava que 'cerca de 500 pessoas participaram da aula inaugural'. Após o fechamento oficial da lista de presença pela coordenação do curso, o número confirmado é de 623 participantes."
     data-cde-antes="Cerca de 500 pessoas participaram da aula inaugural."
     data-cde-depois="623 pessoas participaram da aula inaugural, segundo a lista oficial da coordenação."
     data-cde-data="2026-10-07T16:00:00">
</div>
4

Retificação em declaração

Cor: roxo

Quando usar

Use quando uma fala citada na matéria foi transcrita de forma incorreta, incompleta ou descontextualizada. Comum em entrevistas, coletivas de imprensa e cobertura de aulas magnas, defesas de tese ou pronunciamentos oficiais.

Exemplos de situação

  • A fala do reitor foi transcrita faltando um "não" que mudou totalmente o sentido
  • Uma frase do convidado da aula inaugural foi recortada e saiu descontextualizada
  • A assessoria do pesquisador entrou em contato pedindo retificação de uma declaração
  • O estudante entrevistado reclamou que suas palavras foram alteradas na transcrição

Campos a preencher

Obrigatórios: tipo, motivo, data
Opcionais: titulo, antes, depois

Dica de ouro

Esse tipo de correção é delicado — a redação precisa ter a gravação ou algum registro da fala original para confirmar o que foi dito. Se a correção for a pedido da fonte, mencione isso no campo motivo, para manter transparência sobre a origem da retificação.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-bloco
     data-cde-tipo="declaracao"
     data-cde-titulo="Retificação de declaração"
     data-cde-motivo="A assessoria do reitor entrou em contato com a redação informando que a frase citada foi transcrita de forma incompleta. A versão corrigida reflete o que foi efetivamente dito na coletiva de imprensa, segundo a gravação oficial da assessoria."
     data-cde-antes="A universidade vai cortar o programa de bolsas no próximo semestre."
     data-cde-depois="A universidade vai reformular o programa de bolsas no próximo semestre, mantendo o número de beneficiários."
     data-cde-data="2026-10-07T17:00:00">
</div>
5

Outro tipo de correção

Cor: cinza

Quando usar

Use quando o caso não encaixa nos quatro tipos acima. Útil para correções de créditos (foto, autoria, revisão), ajustes de atribuição institucional ou qualquer caso incomum que ainda assim precise de transparência.

Exemplos de situação

  • O crédito da fotografia foi dado ao fotógrafo errado
  • A autoria da reportagem precisou ser corrigida porque faltou um co-autor
  • A matéria foi marcada como "notícia" mas é na verdade um artigo de opinião
  • O link para o estudo citado estava errado e levava para outra pesquisa

Campos a preencher

Obrigatórios: tipo, motivo, data
Opcionais: titulo, antes, depois

Dica de ouro

Use com moderação. A padronização dos cinco tipos ajuda o leitor a entender rapidamente o que mudou. Se você usar "outro" muitas vezes, provavelmente está perdendo oportunidade de classificar melhor — reveja se não cabe algum dos quatro tipos específicos.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-bloco
     data-cde-tipo="outro"
     data-cde-titulo="Correção de crédito"
     data-cde-motivo="A fotografia que ilustra esta matéria foi inicialmente creditada à Assessoria da UFBA. O crédito correto é do fotógrafo Pedro Lima, estudante do curso de Jornalismo da UFBA, que cedeu a imagem para uso editorial. Pedimos desculpas pela falha."
     data-cde-antes="Foto: Assessoria UFBA"
     data-cde-depois="Foto: Pedro Lima"
     data-cde-data="2026-10-07T17:30:00">
</div>
6

Marcação inline

Cor: rosa (marcação no texto)

Quando usar

Use quando a correção é muito pontual — uma única palavra, nome ou número no meio de um parágrafo — e você quer que o leitor veja exatamente onde foi a mudança, sem interromper a leitura com um quadro grande.

Exemplos de situação

  • O horário do evento estava errado dentro de um parágrafo (14h → 16h)
  • O nome do departamento acadêmico foi corrigido inline no texto
  • A sigla de uma pró-reitoria apareceu trocada em uma única frase
  • Um número de página de referência precisava ser ajustado dentro da citação

Campos a preencher

Obrigatórios: antes, motivo
Opcionais: (nenhum — não aceita título, data, antes/depois estruturado)

Dica de ouro

O inline é feito com <span>, não <div>. Ele vai dentro de um parágrafo, envolvendo exatamente o texto corrigido. Ao passar o mouse (ou tocar no celular), aparece um balãozinho com a explicação. Use só para correções muito pequenas e específicas.

Como aparece ao leitor

A aula inaugural do semestre, promovida pela Faculdade de Comunicação, começou às 16h desta segunda-feira, no Pavilhão de Aulas.

Código para copiar e colar

<p>A aula inaugural do semestre, promovida pela Faculdade de Comunicação, começou às
<span data-cde-inline
      data-cde-antes="14h"
      data-cde-motivo="A versão original informava que o evento começou às 14h; o horário correto foi 16h, segundo a programação oficial da Faculdade.">16h</span>
desta segunda-feira, no Pavilhão de Aulas.</p>
7

Conteúdo novo

Cor: amarelo (temporário)

Quando usar

Use quando a matéria recebeu uma informação nova depois de publicada — mas não é correção, é atualização. Nota oficial que chegou depois, declaração complementar, novo desdobramento de um fato em andamento.

Exemplos de situação

  • A reitoria mandou uma nota de resposta depois da matéria publicada
  • Novos dados foram divulgados pela secretaria do curso
  • Uma segunda fonte confirmou a informação em entrevista posterior
  • A assessoria enviou um esclarecimento complementar (não contestatório)

Campos a preencher

Obrigatórios: data
Opcionais: (o conteúdo em si vai como texto dentro do bloco, não como atributo)

Dica de ouro

Este bloco é temporário — o destaque amarelo some automaticamente após 24 horas, mas o texto permanece integrado ao corpo da matéria. É a solução perfeita para situações em que a matéria "respira" ao longo do dia, com desdobramentos novos.

Como aparece ao leitor

Em nota enviada à redação após a publicação desta matéria, a Pró-Reitoria de Ensino de Graduação informou que o programa de bolsas será mantido integralmente no próximo semestre, com ampliação de 15% no número de beneficiários atendidos.

Código para copiar e colar

<div data-cde-novo data-cde-data="2026-10-07T18:00:00">
  <p>Em nota enviada à redação após a publicação desta matéria, a Pró-Reitoria de Ensino de Graduação informou que o programa de bolsas será mantido integralmente no próximo semestre, com ampliação de 15% no número de beneficiários atendidos.</p>
</div>
8

Trecho excluído

Cor: cinza tracejado (temporário)

Quando usar

Use quando um trecho da matéria precisou ser removido por imprecisão não confirmável, por proteção de uma fonte, por refinamento de edição ou por decisão editorial. Nunca despublique sem deixar rastro.

Exemplos de situação

  • Uma informação não pôde ser confirmada em segunda fonte e foi tirada
  • Um nome de fonte foi retirado para proteção depois de ela pedir anonimato
  • Um parágrafo especulativo foi retirado por decisão editorial
  • Uma citação precisou ser removida porque a fonte alegou que foi gravada sem autorização

Campos a preencher

Obrigatórios: data, original, explicacao
Opcionais: nenhum

Dica de ouro

Este é o único padrão em que você registra o que foi tirado dentro do próprio atributo (data-cde-original), para manter o rastro editorial — mesmo depois que o bloco some, fica documentado nos backups do site. Após 24 horas o bloco desaparece da página pública, mas o registro editorial permanece.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-excluido
     data-cde-data="2026-10-07T18:30:00"
     data-cde-original="Fontes internas da reitoria confirmaram à nossa redação que novos cortes orçamentários estão em discussão para 2027."
     data-cde-explicacao="O trecho foi removido porque a informação não pôde ser confirmada em segunda fonte dentro da janela de apuração desta matéria. A questão segue em acompanhamento pela redação.">
</div>
9

Direito de resposta

Cor: verde-azulado (permanente)

Quando usar

Use para publicar direito de resposta concedido judicialmente ou por acordo entre as partes. O texto da resposta deve ser publicado na íntegra, sem edição editorial. É obrigação legal e ética.

Exemplos de situação

  • Um professor citado na matéria obteve direito de resposta por decisão judicial
  • A direção de uma unidade universitária solicitou direito de resposta e foi concedido por acordo
  • Um estudante entrevistado alegou que foi mal representado e a redação concedeu espaço de resposta
  • Uma empresa parceira da universidade exerceu direito de resposta após matéria crítica

Campos a preencher

Obrigatórios: titulo, data, de, texto
Opcionais: decisao, introducao, rodape

Dica de ouro

Este bloco nunca desaparece, diferente dos de 24h. É permanente, porque é documento legal. O texto do campo data-cde-texto deve ser exatamente o que a parte forneceu, sem qualquer edição da redação — nem para corrigir pontuação. É intocável.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-resposta
     data-cde-titulo="Direito de resposta"
     data-cde-data="2026-10-08T10:00:00"
     data-cde-de="Prof. Dr. João dos Santos, por meio de sua assessoria jurídica"
     data-cde-decisao="Concedido por acordo entre as partes"
     data-cde-introducao="Em cumprimento do acordo firmado entre as partes, publicamos abaixo, na íntegra, o direito de resposta concedido ao Prof. Dr. João dos Santos."
     data-cde-texto="Em matéria publicada por este veículo no dia 7 de outubro de 2026, fui mencionado como responsável por decisões administrativas que não me cabiam. Esclareço que não ocupo cargo de gestão na faculdade desde 2024 e que as decisões citadas são de responsabilidade da atual direção. Reitero meu compromisso com a transparência acadêmica."
     data-cde-rodape="O veículo mantém a íntegra da matéria original disponível, com esta resposta anexada em cumprimento do acordo firmado.">
</div>
10

Botão de reportar erro

Cor: preto (botão)

Quando usar

Coloque ao final de toda matéria. É o canal para o leitor comunicar à redação que encontrou um erro. Clicando no botão, abre um formulário modal com campos para tipo do erro, descrição e e-mail do leitor para resposta.

Exemplos de situação

  • Rodapé de toda matéria publicada no portal da universidade
  • Final de edições especiais ou dossiês acadêmicos
  • Fim de reportagens longas, onde a probabilidade de erro é maior
  • Perto do bloco de "Topo da página" ou outros elementos de navegação

Campos a preencher

Obrigatórios: (nenhum — basta o atributo data-cde-abrir-form)
Opcionais: nenhum

Dica de ouro

Padronize onde o botão aparece — sempre no mesmo lugar, com o mesmo texto em todas as matérias do site. Isso cria familiaridade no leitor e aumenta a chance de ele reportar erros. No mapeamento de 200 sites de notícias feito pela pesquisa, apenas 17% têm esse canal.

Como aparece ao leitor

Código para copiar e colar

<p style="text-align: center; margin: 2em 0;">
  <button data-cde-abrir-form>Comunicar erro nesta matéria</button>
</p>
11

Seção agregadora de correções

Cor: rosa (seção)

Quando usar

Use para montar uma página dedicada que agrega todas as correções do site (ou de uma cobertura específica — eleições, pandemia, greve universitária). É o equivalente à seção "Erramos" da Folha, UOL ou Estadão.

Exemplos de situação

  • Página "Correções" acessível pelo menu principal do portal
  • Página específica para uma cobertura acadêmica longa, com várias matérias
  • Rodapé da home do portal, com as correções mais recentes
  • Seção interna de boletim editorial para a comunidade universitária

Campos a preencher

Obrigatórios: (nenhum — a lista é preenchida automaticamente pelo plugin)
Opcionais: titulo, subtitulo

Dica de ouro

No mapeamento da pesquisa, apenas 3 em 200 sites de notícias brasileiros têm essa seção: Folha, UOL e Estadão. Ter uma seção agregadora é um avanço de transparência. Deixe acessível pelo menu principal do site, não só pelo rodapé.

Como aparece ao leitor

Código para copiar e colar

<div data-cde-lista
     data-cde-titulo="Correções do portal"
     data-cde-subtitulo="Todas as correções, retificações, esclarecimentos e direitos de resposta publicados no portal de notícias da universidade.">
</div>

Erros comuns a evitar

1. Colar o código no editor Visual

Esse é o erro mais frequente. O editor Visual (TinyMCE do WordPress Clássico, Gutenberg padrão, "Editor de Texto" do Elementor) remove os atributos data-cde-* automaticamente. Resultado: você vê o texto, mas as caixas coloridas nunca aparecem.

Solução: sempre use aba Código (Clássico), bloco HTML personalizado (Gutenberg) ou widget HTML (Elementor).

2. Esquecer o campo data

Vários blocos (novo, excluido) dependem do campo data-cde-data para calcular quando devem desaparecer. Se você esquece o campo, o plugin não sabe quando iniciar a janela de 24h.

Solução: sempre preencha data-cde-data no formato AAAA-MM-DDTHH:MM:SS (exemplo: 2026-10-07T14:30:00). Use a data e hora reais da correção.

3. Criar uma nova matéria em vez de corrigir a original

Alguns iniciantes, ao detectar um erro grave, apagam a matéria e publicam outra. Isso quebra todos os links que já foram compartilhados nas redes sociais, WhatsApp e newsletters.

Solução: sempre edite a matéria original na mesma URL. Insira o bloco de correção dentro dela.

4. Preencher o campo "motivo" de forma vaga

Escrever "O texto foi corrigido" não ajuda ninguém. O leitor quer saber o que foi corrigido e por quê.

Solução: use o modelo "Em versão anterior, publicamos X. O correto é Y, conforme fonte Z. A informação foi corrigida." Transparência total.

5. Não corrigir o texto do corpo da matéria

Alguns iniciantes acham que basta inserir o bloco de correção. Não basta — o texto do corpo também precisa ser atualizado para a versão correta.

Solução: ao inserir qualquer bloco de correção, também edite o texto da matéria para refletir a informação correta.

6. Esquecer de propagar a correção nas redes sociais

Se a notícia errada foi para o Instagram, X ou WhatsApp do portal, a correção precisa ir também para esses canais.

Solução: depois de corrigir no site, poste uma errata nas redes sociais e envie uma mensagem no WhatsApp do portal, se houver.

Princípios editoriais

Mais importante do que saber usar os códigos é saber por que você está usando. Alguns princípios da pesquisa que embasa este plugin:

Todo jornalismo erra. Esconder o erro é o problema.

Errar faz parte do fluxo diário. O que corrói a credibilidade do portal não é o erro em si — é a tentativa de escondê-lo.

Transparência é regra, não exceção.

O leitor precisa saber que a notícia mudou, o que mudou e por quê. "Atualização" sem explicação é frequentemente correção disfarçada.

Corrigir é parte do ofício.

A correção não é admissão de fracasso. É afirmação de responsabilidade editorial. Quanto mais visível a correção, mais o portal se afirma como responsável pela informação que publica.

A forma como se corrige importa tanto quanto evitar o erro.

Corrigir de maneira direta e explicativa mostra preocupação com a verdade factual. A demora na admissão do erro pode transformar uma correção pontual em crise.

Nomear a cadeia de responsabilidade.

A decisão editorial sobre como corrigir erros mais graves deve estar nas mãos de alguém previamente determinado — editor-chefe, diretor da redação, coordenador. Isso evita que a responsabilidade recaia só sobre o estudante que escreveu a matéria.

Perguntas frequentes

Posso usar mais de um tipo de correção na mesma matéria?

Sim. Uma matéria pode ter várias correções de tipos diferentes. Cada erro recebe seu bloco próprio, no local apropriado.

Como testo se o plugin está funcionando antes de publicar?

Salve como rascunho e clique em "Visualizar" ou "Preview". O rascunho não vai ao ar, mas você vê como ficaria.

Posso remover um bloco de correção depois de publicado?

Tecnicamente sim, mas não deve. Blocos de correção são registro público do erro cometido. Removê-los é escondê-los. A exceção são os blocos de 24h (novo e excluido), que o próprio plugin faz desaparecer automaticamente.

O que faço se o leitor reportar um erro que não é erro?

Responda ao leitor mesmo assim. "Agradecemos sua mensagem. Verificamos a informação e ela está correta segundo [fonte]. Qualquer dúvida, estamos à disposição." Nem toda comunicação de erro vira correção, mas toda merece resposta.

E se o leitor insistir que o portal está errado?

Verifique com uma segunda fonte independente. Se o leitor tiver razão, agradeça publicamente (com autorização dele) e publique a correção. Creditar o leitor é um gesto de respeito que fortalece a relação com a audiência.

Quem decide se uma correção precisa de errata visível?

A pesquisa recomenda que a decisão editorial sobre casos graves esteja nas mãos de um responsável previamente definido. No portal universitário, isso costuma ser o editor-chefe, o professor responsável ou o coordenador editorial. Em dúvida, consulte.
